ENGINEERING PRINCIPLES (apply at every SDLC step: ideation, planning, building, review, evaluation, iteration)

1. Reuse before you write. Never hand-roll solved problems: authentication/sessions/JWT, OAuth2/OIDC, password hashing, crypto, input validation, routing/HTTP framework, CSRF, rate limiting, security headers, date handling, parsing (CSV/markdown/YAML), logging, email/payment SDKs. Use the established, widely used npm package instead. Custom code is for the product's own domain logic only.
2. Choose well-known libraries: large adoption, actively maintained, permissive license (MIT/ISC/BSD/Apache-2.0), pure JavaScript (no native addons, no install scripts), few transitive dependencies. Prefer the PREFERRED LIBRARIES list; pick something else only when none fits, and say why in the design.
3. Built-ins count as standard: node:sqlite, node:crypto (randomUUID, randomBytes, timingSafeEqual), node:test, node:assert, global fetch (tests only). Do not add a package for something Node already does well.
4. Declare dependencies, never hand-edit package.json or node_modules. Engineers declare needed packages on one line in the reply: `DEPENDENCIES: express, zod`. The factory vets (downloads, maintenance, license, deprecation, vulnerabilities) and installs them. If a package is rejected, choose the suggested alternative or a different standard package.
5. Every imported package must be declared. Do not import anything that was not installed.
6. Libraries that talk to external services (OAuth/OIDC providers, payment, email, cloud) may be wired up, but stay INACTIVE and configuration-driven until the human supplies accounts/credentials (golden rules 3 and 6). Never hardcode secrets; read them from environment variables that default to disabled.
7. Reviewers reject hand-rolled security-sensitive code when a standard library exists. Evaluators flag it. Iteration planners schedule replacing custom implementations with standard libraries before adding new features.
8. Seek enhancement: if a task would go faster or safer with an existing tool, skill, or MCP server, name it in your output ("tooling_suggestions") so the factory's tool scout can evaluate it. Never install or run tools yourself.
